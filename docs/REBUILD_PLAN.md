## 1. Product

**CityMatcher — Find where you'd actually thrive.**

CityMatcher is a relocation decision engine. You describe what matters — budget, climate,
safety, healthcare, walkability, work — and it ranks real European cities with sourced data,
shows the trade-offs, and explains what living there actually costs.

It is not an LLM that invents city statistics. The ranking engine is deterministic,
versioned and testable. AI is an optional interface layer for natural-language input and
grounded explanations. The product works fully with AI disabled.

**Primary audience for v1:** remote workers and young professionals choosing a European base.

### Jobs to be done

1. "Which cities fit my priorities and budget?"
2. "What would my life actually cost there?"
3. "Which of my finalists is best for me?"
4. "Why does this city rank here, and what would I give up?"
5. "How do I share this with my partner / save it for later?"

### Differentiation

- Explainable matching with per-criterion contributions and explicit trade-offs.
- Real budget simulation (rent + living costs vs. net salary), not a single opaque index.
- Honest data: every metric has provenance, a date and a confidence label.
- Deal-breakers are filters, not hidden penalties.
- Works without an account, with shareable preference URLs.

## 2. Decisions

| Decision | Choice | Rationale |
| --- | --- | --- |
| Package manager | pnpm 11, frozen lockfile | Fast, disk-efficient, strict peer resolution, reproducible CI |
| Framework | Next.js App Router + React + TypeScript strict | SSR/SEO for city pages, server-side AI key, one deployable |
| Styling | Tailwind CSS v4 + hand-built component primitives | No runtime dependency, full design control |
| Data | Versioned JSON dataset generated by a reproducible script | Zero hosting/DB cost for v1; easy to move to Postgres later |
| Persistence | Shortlist in `localStorage`; preferences encoded in URL | Anonymous-first, zero backend, GDPR-friendly |
| LLM | Optional Gemini free tier (Groq fallback), server-only | Free at this scale, swappable, deletable |
| Hosting | Vercel Hobby (free), static-compatible routes | Zero cost; migrate to Cloudflare/Pro at monetization |
| Ingestion | Node scripts + Open-Meteo + World Bank APIs | Free, open, reproducible |
| Tests | Vitest for scoring/parsing; Next build as integration gate | Fast, no browser dependency |
| i18n | English UI for v1; copy structured for future FR/ES | Avoid premature complexity |

**Security note:** the original OpenAI key committed in the legacy Angular app must be
revoked by the owner. The new app reads AI keys only from server environment variables.

### Data model

```ts
interface City {
  slug: string;
  name: string;
  country: string;
  countryCode: string;
  region: "western" | "northern" | "southern" | "central" | "eastern";
  population: number;
  lat: number;
  lng: number;
  currency: string;
  climate: { ... monthly highs/lows/rain/sun; tags; annualSunHours };
  cost: { rentOneBed: number; livingSingle: number; totalSingle: number; index: number };
  work: { avgNetSalary: number; salaryCoverage: number; topSectors: string[] };
  metrics: { safety; healthcare; internet; walkability; environment; happiness; publicServices; english };
  confidence: "high" | "medium" | "low";
  sources: SourceRef[];
  editorial: { summary; bestFor; highlights; tradeoffs };
}
```

### Ranking specification (v1)

1. **Hard filters:** region, monthly budget (`rent + living ≤ budget`), climate band, city size.
   If strict filters return fewer than 3 cities, over-budget candidates up to 25% are shown
   and flagged — never silently ignored.
2. **Weights:** the user sets 0 (skip), 1 (nice), 2 (important), 3 (essential) for ten criteria.
3. **Metric scores (0–100):** affordability, safety, healthcare, climate, internet,
   walkability, environment, jobs, happiness, public services, English.
   - Affordability: `100 − 50 × (total / budget)`, clamped. With no budget, inverse cost index
     percentile.
   - Jobs: net salary coverage of local costs, normalized.
   - Climate: match against selected band, plus comfort penalty.
4. **Match score:** weighted mean over chosen criteria only. No hidden denominator.
5. **Tiers:** Excellent ≥ 80, Strong ≥ 65, Fair ≥ 50, Stretch < 50.
6. **Explanation:** top two weighted strengths, biggest weighted trade-off, budget note,
   confidence. Generated from the computed breakdown, never by an LLM.
7. **Version:** `METHODOLOGY_VERSION = "1.0"` stored in share URLs.

## 4. Data strategy

### Sources (v1)

| Domain | Source | Status |
| --- | --- | --- |
| Climate normals | Open-Meteo Archive API (ERA5), 2019–2024 | Automated |
| Country context | World Bank indicators (internet, life expectancy, health spend, PM2.5, GDP PPP) | Automated |
| City catalogue / coordinates | Curated, cross-checked with GeoNames | Seeded |
| Rent, living costs, salaries | Curated public estimates (2024–2025), labelled medium confidence | Seeded |
| Safety, walkability, happiness, services, English | Curated composite estimates, labelled | Seeded |
| Editorial | Hand-written per city | Seeded |

### Rules

- Every displayed metric has a source and an `asOf` date.
- Curated/modelled values are labelled as such; automated values carry their API source.
- No LLM-generated statistics.
- No scraping of sites whose terms prohibit it (Numbeo, Teleport, etc.).
- Data QA enforces ranges, uniqueness, coverage and freshness.
- Dataset is versioned in git; the pipeline is reproducible with `pnpm data:build`.

### Upgrade path

When accounts/email alerts arrive, move the JSON dataset into Postgres (Neon free tier) with
Drizzle. The scoring engine consumes a repository interface, so no UI rewrite is required.

## 5. UX

### Wizard (3 steps)

1. **Non-negotiables:** budget slider/input, region, climate, city size.
2. **Priorities:** ten criteria with 4-level weights, live count of essentials.
3. **Optional context:** net monthly income, job field, household. Used for budget/leftover
   and jobs fit. Skippable.

Natural-language box on step 1: "warm, walkable, safe, under €2,000" → parsed into controls
and shown as chips for confirmation. Rule-based parser is the default; LLM refines it when
configured.

### Results

- Summary header with match count, budget note, share/save actions.
- Sort control and filter chips.
- City cards: rank, match tier, monthly total, rent, salary, top reasons, trade-off,
  profile/compare/save actions.
- Empty state with relax suggestions; over-budget fallback clearly labelled.

### City profile

- Hero with match score (when preferences supplied), verdict, best-for line.
- Real monthly budget panel (rent, living, total, salary leftover).
- Climate chart (12 months, SVG) with annual sunshine/rain.
- Metric bars with source/confidence.
- Work, visas/cost context, highlights/trade-offs.
- Sources with dates, compare/shortlist actions.

### Compare

- 2–4 cities, sticky metric rows, best value highlighted.
- Add/remove via query params; shareable.

### Trust

- Methodology page with formula, weights, limitations.
- Sources page with links, licenses and freshness.
- Confidence labels and "modelled" markers in the UI.

## 10. Risks and mitigations

| Risk | Mitigation |
| --- | --- |
| Curated cost data drifts | `asOf` dates, low/medium confidence labels, quarterly refresh |
| City-level gaps (crime, salaries) | Country-level context with confidence, never fabricated |
| Free-tier limits change | Static dataset; AI optional; swap providers via env |
| Vercel Hobby non-commercial clause | Move to Cloudflare/Pro when monetization starts |
| LLM hallucination | LLM only parses preferences; numbers always come from dataset |
| Scope creep | v1 scope frozen; accounts/alerts/DB deferred |
| Legal/visa liability | Informational only, link official sources, disclaimers |

### Implementation notes

- v1 deliberately ships the dataset as a versioned JSON file rather than Postgres. The
  scoring engine and data access are isolated in `lib/`, so moving to Neon/Drizzle when
  accounts arrive does not require a UI rewrite.
- Only English is shipped. Copy and data structures are locale-ready but no translation
  layer was added in v1.
- The finance/visa/occupation-level data listed in the roadmap is explicitly out of v1 and
  disclosed on the sources page.
- Verification evidence is recorded in `docs/VERIFICATION.md`.
